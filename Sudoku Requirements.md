# 📄 Требования к приложению «Судоку» (v1.0)

> **Статус:** Базовая спецификация  
> **Дата актуализации:** 10.04.2026  
> **Аудитория:** Разработка, QA, Продукт, Дизайн  
> **Цель:** Сформировать единый источник истины для MVP и дальнейшего масштабирования.

---

## 🖥 1. Поддерживаемые платформы

| Платформа | Минимальная версия | Особенности интерфейса |
|-----------|-------------------|------------------------|
| **macOS** | 12 Monterey+ | Нативные меню, `Cmd+Z/C`, системные уведомления, полная поддержка клавиатуры и трекпада |
| **Windows** | 10/11 (x64/ARM64) | Системное меню, `Ctrl+Z/C`, корректное масштабирование DPI, горячие клавиши |
| **Linux** | Ubuntu 22.04+, Fedora 38+, Debian 12+ | Распространение через Flatpak/AppImage, поддержка Wayland/X11, клавиатурная навигация |
| **Android** | 10+ | Тач-управление, экранный цифровой блок, адаптация под вырезы/скругления, системные жесты |

> ⚠️ Приложение должно использовать **единую кодовую базу** с платформенными адаптациями ввода, навигации и системных интеграций.

## 🔹 2. Функциональные требования (ядро игры)

| № | Требование |
|---|------------|
| 2.1 | Отображение стандартной сетки 9×9 с визуальным разделением на 9 блоков 3×3. |
| 2.2 | Генерация или загрузка головоломок с **единственным корректным решением**. |
| 2.3 | Ввод цифр `1–9` через виртуальную клавиатуру, физическую клавиатуру или клики/тапы. |
| 2.4 | Фиксация исходных цифр головоломки (недоступны для редактирования, визуально отличаются). |
| 2.5 | Валидация по правилам Судоку: уникальность цифры в строке, столбце, блоке 3×3. |
| 2.6 | Подсветка конфликтов/ошибок в реальном времени или по кнопке «Проверить». |
| 2.7 | Режим «Заметки» (карандашные пометки): до 9 кандидатов на клетку, быстрое переключение режима. |
| 2.8 | `Undo`/`Redo` с историей минимум 50 шагов и опцией «Очистить всё». |
| 2.9 | Автосохранение состояния при сворачивании, закрытии окна или переключении фокуса. |
| 2.10 | Автоматическое определение завершения игры и показ финального экрана с итогами. |
| 2.11 | Выбор уровня сложности (Лёгкий / Средний / Сложный / Эксперт), влияющий на стартовое заполнение и логику генератора. |

## 🎨 3. Требования к интерфейсу и UX

| № | Требование |
|---|------------|
| 3.1 | Адаптивная компоновка: компактный режим для десктопа, крупный тач-режим для мобильных. |
| 3.2 | При выборе клетки подсвечиваются строка, столбец и блок 3×3. |
| 3.3 | При выборе цифры подсвечиваются все её вхождения на поле. |
| 3.4 | Минимум экранов: старт → игра → результат. Настройки вынесены в сайдбар/шторку. |
| 3.5 | Поддержка навигации клавиатурой (стрелки, `Enter`, `Space`, `Backspace`, цифры). |
| 3.6 | Доступность (a11y): корректная работа с TalkBack/VoiceOver/NVDA, контраст ≥ 4.5:1, масштабируемые элементы. |
| 3.7 | Плавные переходы ≤ 200 мс, отсутствие блокирующих анимаций. |

| № | Требование |

## 🛠 7. Предлагаемый технологический стек

### Варианты реализации

| Стек | Плюсы | Минусы | Рекомендация |
|------|-------|--------|--------------|
| **Flutter 3.24+ (Dart)** | Единая кодовая база для всех 4 платформ, стабильный десктоп, hot reload, богатая экосистема пакетов (`isar`, `flutter_localizations`, `go_router`), высокая производительность UI. | Нативные интеграции требуют плагинов, размер бинарника чуть выше (~15–25 МБ), сообщество меньше Kotlin. | ✅ **Основной выбор** для быстрой кроссплатформенной разработки с фокусом на UI/UX. |
| **Kotlin Multiplatform + Compose Multiplatform** | Полный доступ к нативным API, идеальная производительность, общая бизнес-логика на Kotlin, зрелый экосистемный стек (`sqldelight`, `kotlinx.coroutines`). | UI частично или полностью дублируется на платформах, десктопная стабилизация Compose MP всё ещё требует внимания, сборка сложнее. | 🔶 Альтернатива, если команда уже работает с JVM/Kotlin или планирует глубокие нативные интеграции. |
| **Tauri 2 (Rust) + Web UI** | Минимальный размер бинарника (< 5 МБ), высокая безопасность, веб-стек для UI. | Android-поддержка фрагментирована (требует мостов), сложность поддержки 4 платформ в одном пайплайне. | 🔻 Не рекомендуется для текущих целей. |

### 📌 Итоговая рекомендация: **Flutter (Dart)**
**Обоснование выбора:**
1. **Единая кодовая база** для macOS, Windows, Linux и Android без дублирования UI-логики.
2. **Зрелая десктопная поддержка** (стабильна с 2024 г., активно обновляется в 2025–2026).
3. **Производительность**: собственный рендерер Skia/Impeller обеспечивает 60/120 FPS даже на анимациях сетки и подсветки.
4. **Экосистема**: готовые решения для локальной БД (`isar`, `drift`), навигации (`go_router`), i18n, тестирования.
5. **CI/CD**: `fastlane` + `GitHub Actions` позволяют автоматизировать сборку, подписание и публикацию на всех 4 платформах.
6. **Масштабируемость**: ядро генератора/валидатора легко выносится в отдельный пакет, что упрощает будущий портинг.

### Рекомендуемый архитектурный стек (Flutter)

| Слой | Технология | Назначение |
|------|------------|------------|
| **UI** | Flutter + `flutter_riverpod` или `bloc` | Реактивное состояние, тестопригодность |
| **Логика игры** | Чистый Dart (`sudoku_core`) | Генерация, валидация, заметки, undo/redo |
| **Хранение** | `isar` или `drift (sqflite)` | Быстрая локальная БД, миграции, индексы |
| **Настройки/Конфиг** | `shared_preferences` + `flutter_secure_storage` | Флаги, персональные данные |
| **Локализация** | `flutter_localizations` + `.arb` файлы | RU/EN, масштабируемо на другие языки |
| **Тесты** | `flutter_test`, `mocktail`, `integration_test` | Unit, Widget, E2E на всех платформах |
| **Сборка/Публикация** | `fastlane`, `msix`, `appimage`, `flatpak-builder`, `Play Console` | Автоматизация релизов |

## 🚀 8. Примечание для MVP

Для запуска первой публичной версии достаточно реализовать:  
`2.1–2.5, 2.8, 2.9, 2.10, 2.11` | `3.1–3.3` | `4.1–4.3, 4.6` | `5.1, 5.3`  
**Рекомендуемый стек:** Flutter + Isar + Riverpod/Bloc

Остальные функции добавляются итеративно после сбора метрик удержания, времени сессий и обратной связи. Архитектура должна сразу закладывать разделение `core` ↔ `presentation` ↔ `data`, чтобы избежать технического долга при масштабировании.
